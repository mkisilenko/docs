Use the personal key from [the API quickstart](/developers/api-quickstart) with `Authorization: Bearer`. Requests must come from a trusted backend over HTTPS. Only GET is supported. HEAD, POST, PUT, PATCH, DELETE and OPTIONS return 405. Unknown or duplicate query parameters are rejected.

Test your account connection and integration before production use. See [Validation notes](#validation-notes).

Download the [OpenAPI 3.1 contract](/openapi/whatsapp-v1.json) for machine-readable schemas. The version is the documentation revision, not a promise of client compatibility. Browser Try-It is intentionally disabled; keep keys in your backend.

## GET /api/v1/whatsapp/groups

| Query parameter | Required | Meaning |
| --- | --- | --- |
| `limit` | No | Integer string from 1 to 100. Default: 100. |
| `cursor` | No | Unchanged `next_cursor` from this listing's preceding page. |

Returns:

- `groups`: objects containing `group_id`, `title` and `registered_at`.
- `next_cursor`: a temporary opaque string, or `null` at the end.
- `read_only`: `true`.
- `group_selection`: `client_filter_only`.
- `scope` and `data_notice`: notices explaining account-wide eligible-group access and untrusted captured content.

A group title can be `null`; use `group_id` as the identity even when a title is present.

Group membership is evaluated on each request. A listing does not reserve access or freeze a historical membership list. Follow the cursor even if a page is empty.

## GET /api/v1/whatsapp/messages

| Query parameter | Required | Meaning |
| --- | --- | --- |
| `group_id` | Yes | UUID from the groups endpoint. |
| `since` | No | ISO timestamp with a timezone. Inclusive lower bound, clamped to the current plan window. |
| `limit` | No | Integer string from 1 to 25. Default: 25. |
| `cursor` | No | Unchanged `next_cursor` for this account, group and query. |

Returns:

| Field | Meaning |
| --- | --- |
| `group_id` | Requested group. |
| `message_history_days` | Current plan's history window. |
| `window_start` | Effective lower timestamp bound for this page. |
| `snapshot_end` | Fixed upper timestamp bound for this scan. It does not freeze database insertion state. |
| `messages` | Messages ordered oldest first by stored timestamp, then stored record ID. |
| `next_cursor` | Next page, or `null` at the end. |
| `read_only` | `true`. |
| `data_notice` | Notice about untrusted content and incomplete capture. |

Each message contains:

| Field | Meaning |
| --- | --- |
| `record_id` | Stable stored-record identifier. Use `(group_id, record_id)` for idempotent upserts. |
| `message_id` | Message identifier. It is not sufficient on its own for deduplication. |
| `sent_at` | Stored timestamp exposed by Anyx, not a guarantee of the original device's send time. |
| `sender` | Available sender name, `null` if unavailable, or `Anyx`. |
| `direction` | `inbound` or `outbound`, identifying an incoming group message or an Anyx message. |
| `content` | Full stored text after link redaction. |
| `links_redacted` | Present and `true` when the text changed during redaction. |

The `outbound` label describes an existing message; this API cannot send one.

A rate-limit response can be HTTP 429 with `Retry-After: 60` and this body:

```json
{"error":"rate_limited"}
```

The fictional examples end after one page. A real response with a non-null cursor requires another request.

## Content and paging

Starter includes 7 days, Pro 14 and Max 28. Eligibility and the available window are checked again on each request. Free and legacy Builder are not included by default.

Only live messages captured by Anyx are included. Direct messages, Notes, imported or backfilled history and attachment files are excluded. Credential-bearing URL parameters and Anyx private access links are redacted. That is not comprehensive removal of personal information.

Pages aim for 512 KiB of serialized message payload and may return fewer than `limit`. One oversized message is still returned whole, so 512 KiB is not a hard response ceiling. Continue until `next_cursor` is `null`; do not infer completion from the message count.

Cursors bind the account, group and original `since`. Keep them unchanged. On later message pages omit `since` or repeat the original timestamp. Cursors expire 24 hours after the scan starts. Restart without a cursor when it is invalid, too old or outside the current plan window.

A fixed `snapshot_end` does not prevent late captures with earlier timestamps. Use overlapping scans and periodically revisit the available window. See [the sync guide](/developers/openclaw-crm).

## Errors and retries

Errors contain an `error` code. A 401 response includes `WWW-Authenticate`; a 429 response includes `Retry-After`.

| HTTP | Code | Action |
| --- | --- | --- |
| 400 | `invalid_request` | Correct parameters, values and duplicate query keys. |
| 400 | `invalid_cursor` | Restart the scan without its cursor. This also covers the 24-hour cursor age limit. |
| 401 | `invalid_token` | Stop and reconnect with the current personal key. Check enabled access and rollout eligibility. |
| 403 | `plan_not_eligible`, `plan_unknown` | Resolve account access or plan status. |
| 403 | `origin_forbidden` | Move the integration to its backend; do not expose the key in browser code. |
| 404 | `group_unavailable` | Stop syncing that group and refresh the listing. Foreign and inactive groups have the same response. |
| 405 | `method_not_allowed` | Use GET. |
| 410 | `cursor_expired` | Restart within the current window; the plan or available history may have narrowed. |
| 429 | `rate_limited` | Wait for `Retry-After`, then retry with bounded jitter. |
| 503 | `unavailable` | Use bounded exponential backoff and keep the last successful checkpoint. |

API calls share IP and account quota buckets with MCP and have an additional limit of 30 API requests per account per minute across both routes. The shared quota configuration can vary. Using both transports does not double your allowance.

Rotating or revoking the personal key, or disabling access, affects future requests across both MCP and API clients. It cannot recall data already sent to an integration.

## Validation notes

Authenticated production API reads, pagination and replay have been verified on one owner account. That test did not cover a live message longer than 2,000 characters. Test your own account connection and downstream integration before production use.
